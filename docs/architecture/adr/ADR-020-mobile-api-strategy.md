# ADR-020: Mobile API & Multi-Channel Strategy

## Status

Accepted

## Context

In later phases, a React Native mobile application and an external Dealer Portal will be introduced. Field sales agents will book orders, inspect dealer balances, log dealer visits, and view stock availability while in rural agricultural areas with intermittent 3G/4G cellular connectivity.

## Problem

How should backend APIs and business rules be designed in Phase 1 to guarantee that mobile applications and dealer portals can consume them directly without building duplicate backend services?

## Options Considered

1. **Web-Only APIs First, Separate Mobile Backend Later (BFF)**:
   - _Risk_: Duplicates business logic, creates synchronization lag between web and mobile features.
2. **Omnichannel API-First Architecture**:
   - Every business capability is exposed through stateless, versioned REST endpoints designed from day one to serve web, mobile, and external portals identically.

## Decision

Adopt **Omnichannel API-First Architecture**:

1. **Unified Authentication**:
   - Mobile and Dealer Portal use the same `/api/v1/auth/login` and JWT token refresh mechanisms.
2. **Bandwidth Optimization**:
   - Standard paginated responses, field filtering, and minimal redundant payloads to accommodate low-bandwidth field cellular networks.
3. **Idempotency Readiness for Offline Sync**:
   - Critical transactional endpoints (e.g. sales order creation, collection logging) accept an `X-Idempotency-Key` header generated by the mobile client.
   - If an agent loses signal and the app retries posting an order, the server detects the idempotency key and returns the original response rather than duplicating the order.
4. **Shared Types**:
   - React Native application can import `@shehswar/types` directly from the monorepo.

## Reasoning

Eliminates redundant backend development when mobile development begins and provides robust defenses against duplicate orders caused by spotty mobile networks.

## Trade-offs

Backend endpoints must handle idempotency tracking and compact payload considerations from the outset.

## Consequences

- React Native mobile app and Dealer Portal will plug into existing APIs with zero backend rewrites.
- Zero duplicate orders under unstable network conditions.
